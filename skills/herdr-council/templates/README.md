# 회의 운영 규칙 (herdr-council)

> 한 주제를 조사관 8명이 저마다 다른 자리(플랫폼·관점)에서 조사한다. 감독관까지 9명이 의견을 낸다. 투표로 하나를 고른다.
> 그 결과를 원 주제 헌장(`charter.md`)에 비추어 다음 주제를 만든다. 사용자가 멈출 때까지 반복한다.

이 폴더(`{{HOME}}/`)는 회의록이다. 감독관과 조사관이 모두 이 문서를 따른다. 진행 명령은 agent-operate 플러그인 `herdr-council` 스킬의 `scripts/council.mjs`다(아래 `council <명령>`으로 줄여 쓴다). 플러그인 설치 위치는 판마다 바뀌므로 경로를 이 문서에 박지 않는다 — 감독관은 `/agent-operate:herdr-council` 스킬이 알려 주는 경로로 부른다.

## 0. 스스로 계속 돈다, 그리고 원 주제를 지킨다

- 사용자의 지시 없이 반복한다. 막히면 감독관이 정하고, 무엇을 왜 정했는지 `final.md`나 막힘 기록에 남긴다.
- 라운드는 헌장의 질문에 답을 쌓는다. 다음 주제는 그 연결이 확인된 것만 연다.
- 라운드는 반드시 끝낸다. 의견이 5개 이상이면 투표로 넘어간다. 5개가 안 되면 같은 주제로 한 번 더 조사시키고, 그래도 안 되면 모인 것으로 끝낸다.
- 감독관이 혼자 정하지 않는 것(사용자가 말할 때만): 결과를 위키·ADR 같은 프로젝트 문서로 올리기, 원격으로 밀어 올리기, 기록 삭제, 사용자 계정으로 글·댓글·좋아요·팔로우·메시지 남기기, 계정 설정 변경, 결제.

### 0-1. 원 주제를 지키는 장치

여러 라운드를 돌면 원래 질문에서 멀어진다(직전 결론의 풀린 곳만 따라가고, 투표가 "논제를 고친" 의견에 상을 주고, 끝내는 규칙이 없어서다). 그래서 아래를 둔다.

- **헌장** `charter.md`: 최초 질문, 범위, 답의 형태, 종료 조건. 라운드 1 전에 사용자가 승인한다(`council init`은 승인 전에 라운드를 열지 않는다). 승인 뒤에는 고치지 않고, 바꿀 일이 생기면 새 헌장을 만든다.
- **누적 답** `cumulative.md`: 원 질문에 대해 지금 말할 수 있는 답 한 쪽. 감독관이 라운드 끝마다 갱신한다.
- **프롬프트마다 헌장 + 누적 답 + 직전 `final.md`의 관련 절**을 넣는다(스크립트가 넣는다).
- **투표 근거를 "답한 부분"과 "바꾼 부분"으로 나눈다.** 재정의는 다음 주제 관문에서 다시 검증한다.
- **복귀 라운드**: 3라운드마다, 또는 원 질문 연결이 두 라운드 연속 약하면 연다. 주제는 헌장의 질문 그대로, 지시는 "지금까지 모인 증거로 답하라"다. 결과를 `cumulative.md`에 반영한다.

## 1. 구성

- 감독관(supervisor) — 이 회의를 연 세션. 진행, 취합, 문서 작성, 다음 주제, 막힘 판단. herdr 3x3의 좌상단 pane이다.
- 조사관 8명 — `council.json`의 `roles`. 각자 자리 하나. pane 하나가 세션 하나다.
- 감독관은 조사하지 않는다. 모델이 아는 것만으로 의견을 낸다. 그래서 감독관의 `facts/` 파일은 없다.
- 조사관은 권한 확인 없이 돌고, 경계는 `researcher.md`로 싣는다(opencode는 에이전트 설정 `council-researcher`, Claude Code는 훅을 끄고 시스템 프롬프트로).
- 수집 경로는 `collection.md`(프리셋이 주면)에 있다. 감독관이 라운드 끝마다 막힘 기록을 보고 고친다.

## 2. 라운드 폴더

`{{HOME}}/<YYMMDD-HHMM>/` — 주제를 던진 시각.

```
topic.md     이번 주제 + 원 질문 연결 3칸 + 하위 질문 + 경로 점검 결과
facts/       8개 — 조사관별로 찾은 사실과 주장
opinions/    9개 — 조사관 8 + supervisor.md
votes/       9개 — 무엇에 투표했는지와 그 근거
tabs/        조사관별 탭 장부(브라우저를 쓰는 프리셋)
errors/      조사관별 막힘 기록
final.md     채택 의견 + 근거 + 투표 근거 취합 + 원 주제 세 줄 + 다음 주제
```

**커밋하는 것은 `charter.md`, `cumulative.md`, 각 라운드의 `final.md`뿐이다.** 라운드 원자료(위의 나머지)는 `council new`가 저장소의 git 무시 목록(`.git/info/exclude`)에 넣어 둔다. 원자료에는 수집한 글의 인용과 작업 맥락이 그대로 들어간다.

## 3. 절차

### 1단계 — 주제와 조사

1. `council init "<주제>"` 뒤 감독관이 `topic.md`의 원 질문 연결 3칸(채우는 부분·바뀌는 점·거리)을 채운다. 거리가 4홉을 넘거나 연결이 약하면 주제를 다시 잡는다.
2. 하위 질문을 둘로 나눈다. **문헌 질문**(실험·수치·효과 크기 — 논문 검색), **플랫폼 질문**(그 현상이 현장에서 어떤 말과 어떤 일로 나타나는가 — 각 자리가 잘 주는 것에 맞춰).
3. `council preflight` — 수집 경로를 점검해 `topic.md` 끝에 산 길·죽은 길을 붙인다. 죽은 길은 조사관이 시도하지 않는다. 도구가 죽어 있어도 라운드를 미루지 않는다.
4. `council setup`(첫 라운드만, 살아 있으면 그대로) → `council research` → `council wait research 20`.
5. **감독관 의견은 조사 결과를 보기 전에** `opinions/supervisor.md`로 쓴다.

조사관은 `facts/<이름>.md`(4절 형식)와 `opinions/<이름>.md`(주장·근거·반대 근거·결론)를 쓴다.

### 2단계 — 투표

`council vote` → `council wait vote 20`. 각자 자기 것을 뺀 의견을 읽고 하나를 고른다. `votes/<이름>.md`의 첫 줄은 반드시 `투표: <후보이름>`(기권은 `투표: 기권`과 이유). 감독관도 의견을 전부 읽고 `votes/supervisor.md`를 쓴다. 자기 의견에는 투표하지 않는다(집계에서 무효).

### 3단계 — 확정

`council tally`로 집계한다. 최다 득표 의견을 채택하고, 동점이면 감독관이 근거를 밝히고 고른다. `final.md`에 담는다:

- 투표 결과표, 채택 의견 전문(`<!-- ADOPTED-OPINION -->` 자리를 두고 `council adopt <후보>`), 그 근거, 투표자별 근거, 기권·동점 같은 예외.
- 이 라운드에서 드러난 것, 확인하지 못하고 넘어간 것. "없다"는 문장마다 4-1을 통과했는지 본다.
- 같은 출처를 여럿이 가져왔으면 한 번만 센다. "독립적으로 확인됐다"고 쓰려면 서로 다른 길로 찾았어야 한다.
- 감독관이 막힘 때문에 스스로 정한 것과 그 이유.
- **원 주제 세 줄**: 원 질문에 더한 것 / 원 질문과의 거리(직전보다 가까워졌나, 근거) / 재정의(채택 의견이 논제를 바꿨나, 바뀐 문장과 이유).

### 4단계 — 다음 주제 (관문)

`final.md`의 풀리지 않은 곳과 헌장, 누적 답을 함께 놓고 후보를 만든다. 후보마다 "이 주제가 원 질문에 더하는 것" 한 줄을 적고, 약하면 버린다(버린 이유도 `final.md`에). `cumulative.md`를 갱신하고, 복귀 조건(0-1)을 본 뒤 `council init`으로 다음 라운드를 연다. 사용자에게 묻지 않는다.

## 4. 기록 규칙

### 4-1. "없다"고 쓰는 조건

"0건", "없다"를 쓰려면 아래를 모두 적는다. 하나라도 빠지면 "못 찾음 — 없는 것인지 검색이 안 된 것인지 모름"이라고 쓴다.

1. 그 검색이 "없다"를 말할 수 있는 검색인가(뜻 없는 문자열을 넣어 빈 결과가 오는지 본다).
2. 같은 시점에 뻔히 결과가 있을 질의는 성공했는가.
3. 구절이 0건이면 낱말을 쪼개 다시 물었는가.
4. 본문을 몇 건 읽고 내린 판단인가.

검색 결과의 개수는 증거가 아니다. 제목을 읽고 관련 건수를 따로 센다.

### 4-2. 받아 온 글을 인용 전에 확인한다

- 제목이 찾던 글과 맞는가, 크기가 말이 되는가, 도메인이 내 자리인가. 숫자 0은 의심한다.
- 댓글·답글은 "전체 M개 중 N개 확인"이라고 적는다. 위쪽 몇 개만 보고 여론이라고 쓰지 않는다.
- AI 답변을 붙여 넣은 글의 수치는 원 논문을 열기 전에는 근거로 쓰지 않는다.

### 4-3. facts는 세 절로 쓴다

- `## 수집 경로 상태` — 실패마다 종류를 붙인다: `도구 실패` / `지침 오류` / `플랫폼에 없음(4-1 통과)` / `모름`. 도구 실패를 "자료가 없다"의 근거로 쓰지 않는다.
- `## 플랫폼에서 나온 것` — 내 자리의 글. 조사관의 본래 몫이다.
- `## 문헌에서 나온 것` — 논문·보고서. 원문을 열어 본 것만.

### 4-4. 막힘 기록은 막힌 그 자리에서 쓴다

`<라운드>/errors/<조사관>.md`에 시도한 명령·받은 응답·원인 추정·다음에 간 길을 적는다. 계정 이름, 프로필 주소는 옮겨 적지 않는다. 다른 조사관의 막힘 기록을 읽고 그 길을 써도 된다.

### 4-5. 큰 글은 파일로 받아 필요한 곳만 읽는다

이전 라운드의 `final.md`를 통째로 읽지 않는다. 프롬프트에 들어가는 것은 헌장, 누적 답, 직전 `final.md`의 관련 절이다.

### 4-6. 계정과 할당량을 지킨다

조사는 사용자의 로그인 계정으로 돌 수 있다. 읽기만 한다. 같은 사이트에 쉬지 않고 요청을 보내지 않는다. 할당량이 있는 길은 `collection.md`의 한도를 지킨다.

## 5. 감독관의 막힘 판단표

| 상황 | 감독관이 하는 일 |
|---|---|
| 조사관이 작업 기억 초과로 죽음 | `council compact`(claude)를 보내고, 실패하면 `council revive <역할>`로 그 조사관만 새로 띄운다 |
| 조사관이 꺼져 셸로 돌아감 | `council revive <역할>` 뒤 `council research --only <역할>`. 꺼진 pane에는 보내지 않는다(지시가 셸에 입력된다) |
| 조사관이 20분 넘게 산출물이 없음 | `herdr agent read <이름> --source recent-unwrapped --lines 80`으로 본다. 멈춰 있으면 `--only`로 그 조사관에게만 다시 보내고, 같은 곳에서 또 멈추면 그 라운드는 기권시킨다 |
| 조사관 pane에 시작·승인·신뢰 창 | 대신 누르지 않는다. 사용자에게 알린다 |
| opencode v2 조사관이 웹검색 동의 창("Allow OpenCode to search the web?")에서 멈춤(blocked) | 조사관마다 처음 한 번 뜬다. 대신 누르지 않고 사용자에게 알린다. 사용자가 허락하면 그 pane에서 Allow를 고른다(무인으로 돌릴 거면 라운드 전에 한 번씩 허락해 둔다) |
| 한 자리의 길이 전부 죽음 | 그 조사관은 막힘 기록만 쓰고 기권한다. 라운드는 계속한다 |
| 브라우저 등 공유 도구가 서로 막힘 | 조사관을 4명씩 두 번에 나눠 보낸다(`council.json`의 `staggerS`를 늘린다) |
| 의견이 5개 미만 | 같은 주제로 한 번 더 조사시킨다. 그래도 안 되면 모인 것으로 끝낸다 |
| 스크립트·트리거가 죽음 | 고치고 다시 건다. 고친 내용은 `final.md`에 남긴다 |
| 주제가 같은 자리를 맴돎 | 주제의 방향을 바꾼다. 이유를 `final.md`에 적는다 |
| 원 질문 연결이 두 라운드 연속 안 나옴 / 3라운드가 지남 | 복귀 라운드를 연다 |

## 6. 규칙

- 확인한 것, 출처가 주장한 것, 우리가 추정한 것을 나눠 쓴다. 출처 URL을 남긴다(없으면 "출처 불명").
- 조사 실패를 숨기지 않는다.
- 조사관은 라운드 폴더 아래에만 쓴다. 저장소의 작업 일지·할일·ADR·위키·소스·설정을 건드리지 않는다.
- 위키 링크(`[[...]]`)를 쓰지 않는다(저장소 훅이 깨진 링크로 막을 수 있다).

## 7. 반복

`council wake start [--interval 20]`이 감독관 pane이 쉬고(idle·done) 있을 때마다 아래 지시를 넣는다. 멈추기는 `council wake stop`. 사용자가 "멈춰"라고 하면 감독관이 멈추고 라운드를 열지 않는다.

```
먼저 상태를 본다: council status
1. facts·opinions가 안 찼으면 wait research 20으로 기다린다. 안 찼으면 이번 턴은 여기서 끝낸다.
2. 조사관 의견이 모였는데 supervisor.md가 없으면, 조사 결과를 보기 전에 opinions/supervisor.md를 쓴다.
3. votes가 안 찼으면 vote로 보내고 wait vote 20. 감독관 투표는 의견을 전부 읽고 쓴다.
4. votes가 찼으면 tally로 집계하고 votes를 읽은 뒤 final.md를 쓴다(원 주제 세 줄 포함, adopt로 채택 의견 전문).
5. final.md가 나왔으면 cumulative.md를 갱신하고, 복귀 조건을 확인하고, 막힘 기록으로 collection.md를 고친 뒤 다음 주제를 정해 init → preflight → research.
막히면 5절 판단표대로 감독관이 정한다. 사용자에게 묻지 않는다. 사용자가 멈추라고 하기 전까지 계속한다.
```
